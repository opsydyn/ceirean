# Factory's Own Suite, Run Locally

Recorded 2026-11-21. Prerequisite 2 of
[the Factory assessment](../../assessments/astro-factory-foundation-20261121.md).
**Satisfied.** All 51 of upstream's test files pass outside Astro's CI, and the
tree typechecks once its generated Worker types exist.

## What Was Run

In the scratchpad clone of `withastro/factory` at
`3a01af8566a580c3cefd5d1f06e1884679a1f135`, nothing inside this repository:

| Step         | Command                                           | Result                                      |
| ------------ | ------------------------------------------------- | ------------------------------------------- |
| Install      | `pnpm install --frozen-lockfile --ignore-scripts` | 10.1s, lockfile unchanged                   |
| Tests        | `pnpm test` (`vitest run`)                        | **51 files, 460 tests, all passing, 742ms** |
| Worker types | `pnpm cf-typegen` (`wrangler types`)              | generated offline, no account               |
| Typecheck    | `pnpm check:types` (`tsc --noEmit`)               | clean                                       |

pnpm 10.28.0 came from corepack against the clone's own `packageManager` pin;
Node is 24.15.0 here against upstream's `>=22.19.0`. Dependency lifecycle
scripts were blocked explicitly, in addition to pnpm 10 blocking them by
default. The suite was run twice with identical results.

Nothing reached the network during the test run, nothing started a container,
and no credential was used or requested.

## What This Changes

**The port-not-adopt decision is confirmed.** 460 tests in 742 milliseconds is
a suite of pure unit tests — no Miniflare, no Workers pool, no fixtures that
need a platform. That was the reading taken from `vitest.config.ts` and the
`vi.mock('cloudflare:workers')` stub when the seven covering files were ported
to `bun:test`; running the whole suite confirms it for the other 44 as well.

**Upstream's typecheck has a prerequisite we cannot inherit.** On a fresh clone
`pnpm check:types` fails with `TS2688: Cannot find type definition file for
'./worker-configuration.d.ts'`. That file is gitignored and generated by
`wrangler types` from `wrangler.jsonc`, and it is named in both `types` and
`include` in upstream's `tsconfig.json`. It generates offline and the typecheck
is clean afterwards.

This is the concrete reason the vendored subset needed
`@cloudflare/workers-types` rather than upstream's generated `Env`: their
`Env` describes twelve Durable Object bindings, eight Workflows and two R2
buckets we do not have, so regenerating it here would describe a Worker that
does not exist. Taking the published ambient types instead was right, and now
it is right for a stated reason rather than by accident.

**One version divergence, benign.** Upstream resolves `valibot` to 1.4.2, its
own floor; the vendored subset pins 1.5.0, which already existed in this
repository. The vendored tests pass on 1.5.0 and upstream's pass on 1.4.2, so
the subset works on both. Worth knowing before anyone reconciles the two.

## What This Does Not Prove

460 passing unit tests say the pure logic is sound. They say nothing about
whether Factory works: no container started, no sandbox ran a command, no
webhook was verified, no model provider was called, and
`src/triage/workflow.ts` — the 1,840-line loop closest to our own — has still
not been read, let alone exercised. Upstream's CI covers more than this suite
does, and this run is not a substitute for it.
