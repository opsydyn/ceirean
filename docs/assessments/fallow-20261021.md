## Configuration And Limits

`.fallowrc.json` uses the installed, version-aligned schema. Package exports are
automatic roots. Additional roots cover the CLI, Alchemy definition, Oxlint
config, Bun test files and string-addressed subprocess fixtures. It does not
mark every source file as an entrypoint. Only historical `docs/evidence/**`
archives/reports are excluded; no source or dependency findings are ignored.

The final graph has 74 entrypoints (68 manual, six manifest-derived).
Entry exports are protected by Fallow's default policy, so this is not a complete
minimal-public-API analysis. No TypeScript semantic pass was requested; inferred
type contracts need human review. Boundaries and rule packs are not configured,
as the raw diagnostics explicitly state: their zero counts are not evidence of
an architecture or policy audit. This scan also does not prove absence of unused
local variables, runtime defects or unused transitive package contents.

## Repeat

No convenience package script is provided: a working-directory scan would not
enforce the approved clean-tree, credential-free isolation. An initial draft
script was removed after independent review. Fallow is intentionally not part
of `check`; findings can produce exit 1.

For the same isolation as this evidence, export tracked source into a new
temporary directory, install with `--frozen-lockfile --ignore-scripts`, use a
fresh temporary HOME and an empty inherited environment, and deny network for
the scan. From that snapshot the measured scanner command was:

```sh
node node_modules/fallow/bin/fallow dead-code --format json --quiet \
  --no-cache --no-type-aware --output-file report.json
```

Pass both telemetry kill switches through `env -i`. Do not use `fallow fix`,
remote `extends`, telemetry enable, a cloud integration or `--ci` for this task.
Review all findings before approving any cleanup.
